Experiment 1 – Networking commands, cables & connectors_ □ x

Aim: To study different networking commands and network cables & connectors.

Theory – Networking commands

Networking commands are command-line utilities used to configure, test, troubleshoot and monitor communication between computers. They help to check IP configuration, verify communication with remote devices and analyse network performance.

Command Purpose
ipconfig / ipconfig /all Displays IP address, subnet mask, default gateway, MAC address, DNS and other TCP/IP details
ping Tests connectivity by sending ICMP Echo Request packets and showing the replies, time and loss
tracert Displays the route (hops) taken by packets to reach the destination
pathping Combines ping and tracert; shows packet loss at each hop
netstat Shows active connections, listening ports and protocol statistics
nslookup Finds the IP address of a domain name using DNS
hostname Displays the name of the local computer
getmac Displays the MAC address of the network adapter
arp -a Displays the ARP cache (IP address to MAC address table)

Commands to execute (Command Prompt)

Aim: Simulate a wired LAN using networking devices and test connectivity using the PING utility.

Theory

A Local Area Network (LAN) connects computers within a limited geographical area using networking devices like switches and cables. A central switch (such as Cisco Catalyst 2960) forwards data frames based on MAC addresses without collisions. The PING utility uses ICMP Echo Request (Type 8) and ICMP Echo Reply (Type 0) to test end-to-end reachability and measure round-trip time between hosts. When first communicating, computers use ARP (Address Resolution Protocol) to resolve IP addresses to physical MAC addresses.

Experiment 5 – Network Traffic Analysis using Wireshark_ □ x

Aim: To analyze network traffic using the Wireshark tool: packet capture, display filtering, and layer-by-layer inspection of Ethernet frames, IPv4 packets, ICMP, HTTP/TLS, TCP, and UDP headers.

Theory

Wireshark is an industry-standard open-source packet analyzer. It intercepts network traffic passing across an active network interface card (NIC) and parses raw binary bitstreams into human-readable protocol layers. The Wireshark interface consists of three primary panes:

  • Packet List Pane (Top): Displays a summary of each captured packet (Packet No., Time, Source IP, Destination IP, Protocol, Length, and Info).
  • Packet Details Pane (Middle): Shows protocol header fields in an expandable tree structure corresponding to OSI/TCP-IP layers (Frame → Ethernet II → IPv4 → TCP/UDP → Application).
  • Packet Bytes Pane (Bottom): Displays the actual hexadecimal and ASCII representation of the selected packet.

Wireshark supports two filtering paradigms: Capture Filters (written in Berkeley Packet Filter / BPF syntax to restrict captured traffic before saving to memory) and Display Filters (applied in real-time on captured packets to isolate specific protocols, IP addresses, or flags without losing data).

Procedures

  1. Open Wireshark and select interface: Launch Wireshark and double-click the active network interface showing live traffic activity (e.g., Wi-Fi or Ethernet).
  2. Start capture and generate traffic: Click Start Capturing Packets (blue shark fin icon). Generate real network traffic by opening a web browser or executing the following command in the terminal / command prompt:
  3. Stop packet capture: Allow 20–30 seconds to capture sufficient packets, then click the red square button (Stop Capturing Packets).
  4. Apply display filters: In the filter toolbar at the top, enter display filters such as ip, icmp, tcp, udp, http, or tls and press Enter to isolate target streams.
  5. Inspect Ethernet II (Data Link Layer): Select any packet and expand the Ethernet II section in the Packet Details pane to observe:
    • Source MAC Address: Hardware MAC address of the sending device / host NIC.
    • Destination MAC Address: Hardware MAC address of the default gateway router or destination host.
    • Type: EtherType code (e.g., 0x0800 for IPv4, 0x0806 for ARP, 0x86dd for IPv6).
  6. Inspect IPv4 (Network Layer): Expand Internet Protocol Version 4 to inspect essential IP header fields:
    • Source & Destination IP: Originating host IP and recipient IP.
    • Time to Live (TTL): Hop-limit counter decremented by each router (e.g., 64, 128, or 255).
    • Protocol: Higher-layer protocol identifier (1 for ICMP, 6 for TCP, 17 for UDP).
    • Total Length & Header Checksum: Overall IP packet byte length and integrity verification.
  7. Analyze ICMP (PING) Packets: Apply the icmp display filter to analyze ping packets:
    • Echo (ping) Request: Type 8, Code 0 sent from client host to target.
    • Echo (ping) Reply: Type 0, Code 0 received from target back to client host.
    • Identifier & Sequence Number: Fields used by the operating system to correlate matching requests and replies.
  8. Examine HTTP and TLS Streams: Apply the http or tls filter:
    • HTTP: Inspect plain-text request method (GET / HTTP/1.1), Host, User-Agent, and status code (HTTP/1.1 200 OK).
    • TLS (HTTPS): Observe encrypted transport handshakes: Client Hello (cipher suites offered), Server Hello (cipher suite selected), Certificate exchange, and Encrypted Application Data.
  9. Analyze TCP Header Fields: Apply the tcp filter to analyze reliable transport layer mechanisms:
    • Source & Destination Ports: Ephemeral client port (e.g. 52410) and well-known server port (e.g. 80 or 443).
    • Sequence & Acknowledgment Numbers: Byte-stream tracking for in-order delivery.
    • Control Flags: Observe the 3-Way Handshake: [SYN] → [SYN, ACK] → [ACK], and connection teardown [FIN, ACK].
    • Window Size: Flow control buffer advertised by the receiver.
  10. Analyze UDP Header Fields: Apply the udp filter to analyze connectionless transport mechanisms (e.g., DNS queries):
    • Source & Destination Ports: Client random port and standard service port (e.g. Port 53 for DNS).
    • Length: 8-byte UDP header + payload size.
    • Checksum: Optional error-detection checksum value.
  11. Record Observations & Conclude: Document all captured protocol header values in the observation table and summarize network protocol behaviors.

Experiment 8 – Design and Simulate VLANs_ □ x

Aim: To design and simulate VLANs on a switch/router using Cisco Packet Tracer.

Theory

A Virtual LAN (VLAN) logically divides one physical switch network into separate broadcast domains. This enhances network performance by confining broadcast frames and provides security by isolating distinct functional groups (e.g., Sales vs HR). Switch ports are configured as:

  • Access Ports: Assigned to a single VLAN to connect end devices (PCs) without 802.1Q tags.
  • Trunk Ports (IEEE 802.1Q): Carry traffic for multiple VLANs across a single physical cable by appending a VLAN ID tag to each Ethernet frame header.
  • Router-on-a-Stick: A single physical router interface is configured with logical subinterfaces (e.g. g0/0.10 and g0/0.20) using 802.1Q encapsulation to enable inter-VLAN routing.

Result

VLANs were created and configured successfully on the Cisco switch. Devices in the same VLAN communicated with each other, while communication between different VLANs required inter-VLAN routing.

Conclusion

VLANs logically divide a physical switch network into separate broadcast domains. They improve network organization, security, and traffic management. Router-on-a-stick enables communication between VLANs through a trunk link and router subinterfaces.
